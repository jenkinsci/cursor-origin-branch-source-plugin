When checked, this credential may be used freely in Pipeline steps such as withCredentials and withGit. An unrestricted access token will be sent to the agent and available for use from user-defined scripts. These might be used to make REST API calls, push tags to the Git server, and so on.

Be very careful about using this option. The token will be able to access any repositories on which the app is installed, and be granted all of its permissions. If some users of the controller able to define jobs or edit build scripts might not be fully trusted, it is advisable to define a separate app installed on specific repositories and with minimal permissions, then create a separate credential object on a folder dedicated to this purpose.

When unchecked (the default), the credential is restricted. It may be used freely by REST API calls inside the controller, such as for branch indexing; or by Git operations inside the controller, such as library checkouts. It may also be passed to an agent for use in checkout scm, but the resulting token will be limited to the one repository and granted only permission to read repository contents: the minimum necessary for that git clone to work.
